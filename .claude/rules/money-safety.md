# 돈 안전장치 (money safety)

orbit 의 버그는 곧 실제 손실이다. 이 문서의 규칙은 편의·성능·간결함보다 우선한다.

## 1. Claude 의 권한 경계

- Claude 는 **실주문을 실행하지 않는다**. 실거래 모드로 엔진을 띄우거나, 실거래 키로 주문 API 를 호출하는 명령을 실행하지 않는다
- **실거래 전환·예산/한도 상향·자산 화이트리스트 추가는 사람만** 한다. Claude 는 코드와 점검표(`go-live-check` 스킬)까지만
- 테스트·개발은 항상 dry-run 또는 mock 브로커로

## 2. 금액·수량

- 금액·가격·수량은 전부 `decimal.Decimal`. `float` 금지 (지표 계산용 pandas 시리즈는 예외 — 주문 금액으로 넘어갈 때 `Decimal` 로 변환 + 거래소 호가·수량 단위로 내림)
- 반올림 방향: 매수 수량·주문 금액은 **내림**. 예산을 넘는 쪽으로 반올림하지 않는다
- 통화를 섞지 않는다 (KRW / USD 를 같은 필드에 담지 않음). 금액 타입에 통화를 같이 들고 다닌다

## 3. 가상 장부 (예산 격리)

계좌에 사용자가 직접 넣은 돈과 직접 산 종목이 같이 있다. 엔진은 **계좌 잔고를 "쓸 수 있는 돈"으로 해석하지 않는다**.

- `가용 예산 = 배정 예산 + 실현 손익 − 엔진 보유분 매수 원가 − 미체결 주문 예약금`
- 엔진은 **자기 주문(client order id)으로 산 수량만** 보유분으로 인정하고, 그 수량까지만 판다
- 배정 예산은 설정에서만 바뀌고, 변경은 장부에 이벤트로 기록된다
- 실현 수익을 예산에 재투입할지는 설정값 (기본: 재투입 안 함)

## 4. 다중 방어선 (전부 필수, 하나만 믿지 않는다)

| 방어선 | 내용 |
|---|---|
| 하드 리밋 | 총 예산, 1회 주문 금액 상한, 하루 주문 횟수 상한. 장부와 **독립된 코드 경로**에서 한 번 더 검사 |
| 리스크 가드 | 모든 주문은 가드를 통과해야 브로커에 도달. 가드 우회 경로를 만들지 않는다 |
| 대조(reconcile) | 매 실행 시작 시 장부상 엔진 보유분 ↔ 실제 계좌 비교. 실제가 장부보다 적거나 설명 안 되는 차이 → **즉시 정지 + 알림**. 추측해서 맞추지 않는다 |
| 킬 스위치 | 대시보드·텔레그램·파일 플래그 어느 쪽으로도 즉시 전체 정지. 정지 상태에서는 신규 주문 0 |
| dry-run 기본값 | 설정 누락·파싱 실패 시 dry-run 으로 떨어진다 (fail-safe) |

## 5. 주문

- **지정가만**. 시장가 주문 코드 경로를 만들지 않는다
- 모든 주문에 멱등 키(client order id). 재시도로 같은 주문이 두 번 나가지 않게
- 주문 직후 상태를 조회해 체결/미체결/거부를 장부에 반영. 응답 타임아웃은 "실패"가 아니라 "불명" — 조회로 확정하기 전에는 재주문 금지
- 루프 안에서 주문하지 않는다. 한 실행에서 전략당 주문 1건이 기본, 그 이상은 명시적 설계 + 테스트
- 레버리지·공매도·선물·마진·출금 API 를 호출하는 코드를 만들지 않는다

## 6. API 키

- 업비트 키: 자산 조회 + 주문만. **출금 권한 금지**, 허용 IP 등록
- 토스 키: 필요한 scope 만
- 키는 서버 env 에만. 코드·설정 예시·로그·에러 메시지에 노출 금지 (→ [secrets-and-privacy](secrets-and-privacy.md))

## 7. 테스트로 강제

- 장부·가드·주문 경로는 단위 테스트 필수. 특히: 예산 초과 거부, 사용자 보유분 매도 거부, 타임아웃 후 재주문 안 함, 킬 스위치 후 주문 0, 설정 누락 시 dry-run
- 이 영역의 버그 수정은 재현 테스트 먼저 (→ [incident-workflow](incident-workflow.md))
