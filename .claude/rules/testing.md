# 테스트 작성

테스트는 **코드가 지켜야 할 규칙**을 검증한다. 구현을 끝낸 뒤 지금 코드가 내는 값을 그대로 옮겨 적은 테스트는, 코드가 틀려도 같이 틀린 채 통과한다. 이 레포는 뮤테이션 테스트를 쓰지 않으므로 아래 원칙으로 빠진 규칙을 막는다

## 규칙을 먼저 적는다

- 테스트 이름에 규칙을 문장으로 적는다 — `test_엔진이_산_것보다_많이_팔면_거부`, `test_같은_날_다시_돌려도_주문은_한_번`
- 기대값은 코드가 아니라 규칙에서 손으로 계산한다 — 주석에 식을 남김 (`# 7300 × 1.03 × 1.01`)
- 규칙이 **깨지는 입력**을 넣는다
  - 합산·이월을 보는 데이터는 0 이 아닌 서로 다른 값 — 전부 0 이거나 같으면 초기화·뒤바뀜 버그와 구분이 안 됨
  - 경계와 분기 양쪽 — 같을 때·직전·직후, 0, 상한, 월말·연말, 휴장일 전후, 서머타임 전후
  - 여러 건이 섞인 상태 — 매수·매도·예산 변경이 섞인 장부, 같은 칸에 기록 여러 줄, 시세 없는 구성 종목 섞임
- 외부 응답을 흉내 낼 때(가짜 토스·업비트·운용사)는 **요청 인자**도 검증한다 — 가짜는 조건과 상관없이 같은 값을 돌려주므로 결과만 보면 조건(기준 시각·종목·기간)을 지워도 통과함

## 예시 나열보다 규칙 전체를 거는 테스트

새 개념(주문 상태·신호 상태·규칙 종류 등)이 들어왔을 때 반영이 빠진 곳이 **실패로 드러나는** 형태를 우선한다

- **항등식** — 모든 경우를 섞은 데이터로 식이 성립하는지
  - 장부: `현금 = 예산 + 매도 대금 − 매수 비용(수수료 포함)`, `실현 손익 + 남은 원가 = 판 금액 + 보유 원가 − 들어간 돈`
  - 백테스트: 기준가(NAV) 는 입금으로 바뀌지 않음, 기간별 결과를 이으면 전체와 맞음
- **두 계산 일치** — "같은 함수·같은 결과" 라고 정한 두 경로를 같은 데이터로 돌려 비교
  - 백테스트와 dry-run 의 판단·수량 계산, 신호와 백테스트의 판단, 리스크 가드와 장부의 예산 계산
- **열거형 전수 순회** — 상태마다 분류를 정하는 표 (`STANCE: Record<Stance, …>`, 파이썬은 `for s in Stance`). 값을 추가하면 분류를 정하기 전까지 타입 검사·테스트가 깨지게

## 쓰지 않는 것

- 검증 없는 테스트, `is not None` 뿐인 테스트, 가짜가 돌려준 값을 다시 확인만 하는 테스트
- 같은 파일의 다른 테스트와 입력·검증이 같은 테스트 — 입력만 다르면 `pytest.mark.parametrize` 하나로
- 라이브러리 기능만 거는 테스트 (pydantic 의 타입 변환·`Field(gt=0)` 자체) — 도메인 규칙(허용 종목·돌파형 규칙 거부)만
- 분기 몇 줄짜리 도우미의 단독 테스트 — 그 도우미를 쓰는 쪽 테스트에서 확인
- 테스트 이름·주석에 내부 문서 번호 (ADR·plan 번호) — 공개 레포에 문서가 없어 뜻이 없음
- **실제 종목·시세·금액** — 공개 레포. 픽스처는 예시 종목코드(`KRX-100000`, `SPY`)와 가짜 가격

## 실행 환경

- 실제 거래소·토스·운용사 API 에 붙는 테스트를 만들지 않는다 — 결과가 흔들리고 키·IP 가 필요함. `httpx.MockTransport`·가짜 소스로
- 시각은 인자로 주입 (`now`, `today`) — `datetime.now()` 를 테스트가 기다리지 않게
- 시간대 규칙은 UTC·뉴욕·서울을 섞은 입력으로 — 개발 PC 가 KST 라 시간대 처리가 빠져도 로컬에선 통과할 수 있음
- 돈 경로(장부·가드·주문)는 커밋마다 테스트 통과 상태 (→ [money-safety](money-safety.md))
