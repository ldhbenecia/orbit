# 사고 대응

## 인자

$ARGUMENTS — 무슨 일이 있었는지 한 줄

## 절차

[incident-workflow](../../rules/incident-workflow.md) 순서를 그대로 따른다.

1. **정지 확인** — 엔진이 멈췄는지 사용자에게 확인. 안 멈췄으면 킬 스위치 방법을 안내 (Claude 가 실거래 엔진을 조작하지 않음)
2. **키 노출이면** — 즉시 키 폐기·재발급 안내가 최우선. 이력 정리는 그다음
3. **사실 확정** — 장부·주문 기록·로그로 타임라인 구성. 거래소 내역은 사용자가 확인해 알려줌. 모르는 건 "미확인"으로 남김
4. **심각도** — S1 실제 손실 / S2 near-miss / S3 운영 불편
5. **재현 테스트** — 실패하는 테스트 먼저. 커밋: `test(<scope>): <사고 요지> 재현`
6. **수정** — 같은 종류의 다른 경로도 점검. 커밋 메시지에 금액·계좌 정보 금지
7. **문서** — `docs/incidents/YYYY-MM-DD-<slug>.md` 를 템플릿으로 작성 (로컬 전용이라 실제 금액 기록 가능)
8. **재발 방지** — 새 테스트·가드·룰 항목을 체크박스로. 룰이 바뀌면 `.claude/rules/` 갱신까지
9. **재개 조건** — 테스트 통과 + 대조 일치 + 사용자 확인. 재개는 사용자가
